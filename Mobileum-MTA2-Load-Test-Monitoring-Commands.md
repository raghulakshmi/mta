# Mobileum MTA2 Load-Test Monitoring Commands

## Purpose

This command sheet collects the monitoring and post-test analysis commands used during the controlled MTA2 SMTP / Exim load test.

The monitoring files are expected under a directory similar to:

```text
/home/ubuntu/mta/mta2-loadtest-YYYYMMDD-HHMMSS/
```

The MTA1 load-generator result log, when created using the earlier test command, is expected on **MTA1**, not MTA2:

```text
/home/ubuntu/mta/mta2-loadtest-run.log
```

---

## 1. Locate the latest monitoring directory on MTA2

Run on **MTA2**:

```bash
MONDIR=$(ls -dt "$HOME"/mta/mta2-loadtest-* 2>/dev/null | head -1)

echo "$MONDIR"
ls -lh "$MONDIR"
```

Expected monitoring files include:

```text
cpu.log
exim-process.log
disk.log
vmstat.log
queue-memory.log
monitor.pids
```

Run on **MTA2**:

## 3. Calculate peak RAM used and lowest available RAM

Run on **MTA2**:

```bash
awk '
/mem_used_mb=/ {
    for (i=1; i<=NF; i++) {
        split($i,a,"=")

        if (a[1]=="mem_used_mb") {
            if (a[2] > max_used)
                max_used=a[2]
        }

        if (a[1]=="mem_available_mb") {
            if (min_avail==0 || a[2] < min_avail)
                min_avail=a[2]
        }
    }
}
END {
    printf "Peak memory used     : %.0f MB (%.2f GiB)\n", max_used, max_used/1024
    printf "Lowest memory avail  : %.0f MB (%.2f GiB)\n", min_avail, min_avail/1024
}' "$MONDIR/queue-memory.log"
```

Alternative compact version:

```bash
awk '
/mem_used_mb=/ {
    for (i=1; i<=NF; i++) {
        split($i,a,"=")

        if (a[1]=="mem_used_mb" && a[2]>max)
            max=a[2]

        if (a[1]=="mem_available_mb" &&
           (min==0 || a[2]<min))
            min=a[2]
    }
}
END {
    printf "Peak memory used   : %.0f MB (%.2f GiB)\n",max,max/1024
    printf "Lowest available   : %.0f MB (%.2f GiB)\n",min,min/1024
}' "$MONDIR/queue-memory.log"
```

## 5. Calculate peak total CPU utilization

`mpstat` reports `%idle`, so total CPU utilization is calculated as:

```text
CPU utilization = 100 - %idle
```

Run on **MTA2**:

```bash
awk '
/ all / && $NF ~ /^[0-9.]+$/ {
    cpu=100-$NF
    if (cpu > max)
        max=cpu
}
END {
    printf "Peak total CPU utilization: %.2f%%\n", max
}' "$MONDIR/cpu.log"
```

Observed during the current test window:

```text
Peak total CPU utilization: 49.69%
```

## 6. View Exim process CPU / RAM / I/O history

Run on **MTA2**:

```bash

```

For a cleaner recent view:


This file is generated by `pidstat` and is useful for separating Exim-specific resource consumption from overall host utilization.

## 8. Calculate peak EBS write metrics across the full test

Run on **MTA2**:

```bash
awk '
$1=="nvme1n1" {
    if ($8  > max_ws)    max_ws=$8
    if ($9  > max_wkb)   max_wkb=$9
    if ($12 > max_await) max_await=$12
    if ($22 > max_aq)    max_aq=$22
    if ($23 > max_util)  max_util=$23
}
END {
    printf "Peak writes/sec       : %.2f\n", max_ws
    printf "Peak write KB/sec     : %.2f\n", max_wkb
    printf "Peak write latency    : %.2f ms\n", max_await
    printf "Peak queue depth      : %.2f\n", max_aq
    printf "Peak disk utilization : %.2f%%\n", max_util
}' "$MONDIR/disk.log"
```

## 10. Calculate peak CPU I/O wait

On the standard Ubuntu `vmstat` output used here, column 16 is `wa`.

Run on **MTA2**:

```bash
awk '
NR > 2 && $16 ~ /^[0-9]+$/ {
    if ($16 > max) max=$16
}
END {
    printf "Peak CPU I/O wait: %d%%\n", max
}' "$MONDIR/vmstat.log"
```

## 13. Check the load-generator result on MTA1

The load generator was run from **MTA1**, so this file will normally **not exist on MTA2**.

Run this on **MTA1**:

```bash
tail -30 ~/mta/mta2-loadtest-run.log
```

The important final fields are:

```text
BATCH=
SENT=
FAILED=
SECONDS=
MESSAGES_PER_SECOND=
APPROX_MB_PER_SECOND=
```

If the file does not exist on MTA1, locate likely load-test files with:

```bash
find ~/mta -maxdepth 1 -type f \
  \( -name '*loadtest*' -o -name '*load-test*' \) \
  -printf '%TY-%Tm-%Td %TH:%TM:%TS %p\n' \
  | sort -r
```

You can also inspect recent files in the MTA working directory:

```bash
ls -lht ~/mta | head -30
```

If the generator was run without `tee ~/mta/mta2-loadtest-run.log`, there will be no saved result file. In that case, the batch can still be reconstructed from Exim logs on MTA2, but the generator's exact `SECONDS`, `MESSAGES_PER_SECOND`, and `APPROX_MB_PER_SECOND` values will not be recoverable unless they were captured elsewhere.

## 14. Recover the actual batch ID from MTA2 logs

Do not use a placeholder such as:

```bash
BATCH='MTA2-LOAD-20260922T...Z'
```

The literal `...` will match nothing.

Search for actual load-test batch identifiers:

```bash
sudo grep -oE 'MTA2-LOAD-[0-9]{8}T[0-9]{6}Z' /var/log/exim4/mainlog \
  | sort -u
```

For the most recent batch:

```bash
BATCH=$(sudo grep -oE 'MTA2-LOAD-[0-9]{8}T[0-9]{6}Z' /var/log/exim4/mainlog \
  | tail -1)

echo "$BATCH"
```

Then capture Exim IDs belonging to that batch:

```bash
sudo grep -F "$BATCH" /var/log/exim4/mainlog \
  | awk '/ <= / {print $3}' \
  | sort -u \
  > "/tmp/${BATCH}.ids"

wc -l "/tmp/${BATCH}.ids"
```
